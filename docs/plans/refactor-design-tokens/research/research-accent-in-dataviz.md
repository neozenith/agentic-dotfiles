# Is there a job for a *second* accent in data-vis and diagramming?

Surfaces: plotly / cytoscape / mermaid / draw.io / deck.gl — not buttons. Premise: a neutral ramp, a golden-angle **categorical walk** anchored on the primary accent (6–8 hues), and a **status channel** already exist. Researched 2026-09-03. `[UNVERIFIED]` marks anything not confirmed from a primary source.

## 1. Chart / viz systems

| System | Distinct accent/highlight hue? | Mechanism | Name |
|---|---|---|---|
| Highcharts | **YES** | own 5-step ramp | `--highcharts-highlight-color-{100,80,60,20,10}` |
| Cytoscape.js | **YES** (selection only) | hard-coded default sheet | `:selected` → `#0169D9` |
| deck.gl | **YES** | base-layer prop | `highlightColor` |
| Plotly | **PARTIAL** | one hard-coded hue + empty slots | `layout.activeshape.fillcolor` |
| Vega / vega-themes | NO accent; YES a single-mark role | per-theme constant | `markColor` → `mark.color` |
| ECharts | **NO** | derived lightness lift | `liftColor()` on `emphasis` |
| Carbon Charts | **NO** | derived lightness modifier | `--cds-charts-*-hovered` |
| Observable Plot | **NO** | — | `"accent"` is only a d3 scheme name |

**IBM Carbon Charts.** Tokens generate as `--cds-charts-#{$token}` with an auto-derived `-hovered` variant = `color.adjust($color, $lightness: -7%)` — emphasis is a **lightness delta, not a hue** ([_colors.scss](https://raw.githubusercontent.com/carbon-design-system/carbon-charts/main/packages/core/scss/_colors.scss)). The categorical palette is **independent of the product's primary**: it imports `@carbon/colors` raw, entry 1 = `getColorValue(purple, 70)` `#6929c4`, not Carbon's brand blue ([_color-palette.scss](https://raw.githubusercontent.com/carbon-design-system/carbon-charts/main/packages/core/scss/_color-palette.scss)). Docs name exactly three families — categorical, sequential (incl. diverging), alert ([docs](https://carbondesignsystem.com/data-visualization/color-palettes/)). **Confirmed absence:** no highlight, selected, reference-line or zero-line token in [_tokens.scss](https://raw.githubusercontent.com/carbon-design-system/carbon-charts/main/packages/core/scss/_tokens.scss).

**Vega / vega-themes.** A single-series primary-mark role exists, distinct from the category range: each theme sets a module-scope `markColor` fanned across `arc.fill`/`line.stroke`/`rect.fill`/`symbol.fill`; Vega-Lite's default is `defaultMarkConfig.color = '#4c78a8'` ([mark.ts](https://raw.githubusercontent.com/vega/vega-lite/main/src/mark.ts)). It is not always category[0] — `theme-latimes` uses `#82c6df`, absent from its `category-6` array ([theme-latimes.ts](https://raw.githubusercontent.com/vega/vega-themes/main/src/theme-latimes.ts)). **Confirmed absence:** no `accent`/`highlight`/`emphasis`/`selected` key anywhere in [vega-themes/src](https://github.com/vega/vega-themes/tree/main/src) or [vega-lite config](https://raw.githubusercontent.com/vega/vega-lite/main/site/docs/config.md).

**Plotly.** A stock template carries only `colorway`, `colorscale.{sequential,sequentialminus,diverging}`, `paper_bgcolor`, `plot_bgcolor`, `font.color`, axis `gridcolor`/`linecolor`/`zerolinecolor` — **no highlight colour** ([plotly.json](https://raw.githubusercontent.com/plotly/plotly.py/master/plotly/package_data/templates/plotly.json)). The schema does hard-code `layout.activeshape.fillcolor` = `'rgb(255,0,255)'` — magenta, deliberately outside colorway and status ([attributes.js](https://raw.githubusercontent.com/plotly/plotly.js/master/src/components/shapes/draw_newshape/attributes.js)) — and defines `scatter.selected.marker.color` / `.unselected.marker.color` as `valType:'color'` **with no default**: a real role slot, deliberately left unfilled ([scatter/attributes.js](https://raw.githubusercontent.com/plotly/plotly.js/master/src/traces/scatter/attributes.js)).

**ECharts.** `SPECIAL_STATES = ['emphasis','blur','select']` but emphasis ships **no hue**: default `emphasisStyle.fill = liftColor(fromFill)` = `lift(color, -0.1)`, a 10% lightness lift; blur is `opacity * 0.1` ([states.ts](https://raw.githubusercontent.com/apache/echarts/master/src/util/states.ts)). Line series' default emphasis is geometric — `emphasis: { scale: true }` ([LineSeries.ts](https://raw.githubusercontent.com/apache/echarts/master/src/chart/line/LineSeries.ts)).

**Highcharts — the one true `highlightColor`.** Four cleanly separated CSS families in [highcharts.css](https://raw.githubusercontent.com/highcharts/highcharts/master/css/highcharts.css): categorical `--highcharts-color-0..9`; neutrals `--highcharts-neutral-color-*`; status `--highcharts-positive-color:#06b535` / `--highcharts-negative-color:#f21313`; and **highlight** `--highcharts-highlight-color-100:#0022ff` (+80/60/20/10), a blue distinct from every categorical entry. It drives `.highcharts-selection-marker`, `.highcharts-crosshair-category`, `.highcharts-plot-band`, `.highcharts-navigator-*`, `.highcharts-button-pressed`, `.highcharts-drilldown-axis-label`; mirrored in JS as `palette.light.highlightColor` ([themes](https://www.highcharts.com/docs/chart-design-and-style/themes)). Its *states* stay modifiers: `states.inactive.opacity: 0.2`, `column.states.hover.brightness: 0.2` ([SeriesDefaults.ts](https://raw.githubusercontent.com/highcharts/highcharts/master/ts/Core/Series/SeriesDefaults.ts)).

**Observable Plot. Confirmed absence:** `"accent"` appears only as a d3 scheme name in `categoricalSchemes` ([schemes.js](https://raw.githubusercontent.com/observablehq/plot/main/src/scales/schemes.js)); Plot has no interaction-state colour model at all.

**Cytoscape.js.** The shipped default stylesheet sets `:selected` → `background-color`, `line-color` and all four arrow colours to **`#0169D9`**, against `#999` defaults; `:parent:selected` → `#CCE1F9`/`#aec8e5`; `:active` → `overlay-color: black, overlay-opacity: 0.25`; core chrome `selection-box-color: '#ddd'` ([properties.mjs](https://raw.githubusercontent.com/cytoscape/cytoscape.js/unstable/src/style/properties.mjs), [style docs](https://js.cytoscape.org/#style)). One chromatic selection hue; hover/active is a **neutral scrim**. Highlighted-path demos set an author-chosen class colour — nothing is shipped.

**deck.gl.** Base `Layer` defines `autoHighlight` (default `false`), `highlightedObjectIndex` (`null`) and **`highlightColor`, default `[0,0,128,128]`** — "RGBA color to blend with the highlighted object" ([Layer docs](https://deck.gl/docs/api-reference/core/layer)). One dedicated highlight colour, blended not replaced.

## 2. Diagram systems

**Mermaid — the decisive finding: `secondaryColor` IS the categorical walk, not a second brand hue.** From [theme-base.js](https://github.com/mermaid-js/mermaid/blob/develop/packages/mermaid/src/themes/theme-base.js) ([docs](https://mermaid.js.org/config/theming.html)):

```js
this.secondaryColor = this.secondaryColor || adjust(this.primaryColor, { h: -120 });
this.tertiaryColor  = this.tertiaryColor  || adjust(this.primaryColor, { h: 180, l: 5 });
this.cScale0 = this.primaryColor;  this.cScale1 = this.secondaryColor;  this.cScale2 = this.tertiaryColor;
this.cScale3 = adjust(this.primaryColor, { h: 30 });   // … cScale4 h:60 … cScale11 h:330
```

Classifying the variables it accepts:
- **STRUCTURAL** — `background`, `lineColor` (`= invert(background)`), `mainBkg`/`nodeBkg` (`= primaryColor`), `nodeBorder`, `edgeLabelBackground`, `clusterBkg` (`= tertiaryColor`), `altBackground` (`= tertiaryColor`), `rectBkgColor`, `sectionBkgColor`, `activationBkgColor` (`= secondaryColor`), `transitionColor`.
- **CATEGORICAL** — `cScale0..cScale11` (a 30°-step hue rotation of `primaryColor`), `pie1..pie6` (`pie1..3` = primary/secondary/tertiary, `pie4..6` the same at `l:-10`), plus `git*`.
- **EMPHASIS / STATE** — exists only in gantt, and **none of it is a second brand hue**: `activeTaskBkgColor = lighten(primaryColor, 23)` (lightness), `doneTaskBkgColor = 'lightgrey'` (neutral), `critBkgColor = 'red'` (status).

So mermaid's "secondary/tertiary" are *derived hue-walk slots* that also paint alt-surfaces (cluster/subgraph backgrounds, sequence activations). A system that already owns a categorical walk **already supplies them**.

**draw.io / mxGraph.** One dedicated highlight hue, deliberately garish and outside any content palette: `HIGHLIGHT_COLOR: '#00FF00'`, `VERTEX_SELECTION_COLOR: '#00FF00'`, `EDGE_SELECTION_COLOR: '#00FF00'`, `OUTLINE_HIGHLIGHT_COLOR: '#00FF00'`, `DEFAULT_VALID_COLOR: '#00FF00'`, `DEFAULT_INVALID_COLOR: '#FF0000'`, `GUIDE_COLOR: '#FF0000'` ([mxConstants.js](https://github.com/jgraph/mxgraph/blob/master/javascript/src/js/util/mxConstants.js)). **[UNVERIFIED]** `Editor.defaultColorSchemes` was not located in the 441 KB `Editor.js`, so the two-accent question for the *style presets* is unresolved; the classic default pair `#dae8fc`/`#6c8ebf` is likewise unconfirmed here.

**Excalidraw — a flat categorical picker, no accent concept.** `COLOR_PALETTE` is open-color: twelve hue families (`gray, red, pink, grape, violet, blue, cyan, teal, green, yellow, orange, bronze`) × 5 shades, plus `black`/`white`/`transparent`. Five top-pick slots: stroke = `black, red, green, blue, yellow` @index 4; background = `transparent, red, green, blue, yellow` @index 1 ([colors.ts](https://github.com/excalidraw/excalidraw/blob/master/packages/common/src/colors.ts)). **Confirmed absence:** no accent, highlight, emphasis or status role — the picker is purely nominal.

## 3. Theory — emphasis as a role, and the harm evidence

**Emphasis is real but is usually *achromatic subtraction*, not a second hue.** NN/g: "Start with gray… then strategically add color to highlight the values or series that are most important" ([contrast in charts](https://www.nngroup.com/articles/contrast-charts/)) — and, **confirmed absence**, that article never says how many highlight colours are permissible. Haroz & Whitney's design-relevant sentence: "The degree to which the targets pop-out… is modulated by the extent to which all the other colors are grouped" ([dissertation ch.](https://escholarship.org/content/qt4cs762vs/qt4cs762vs.pdf)); their reported recommendations are binning and "graying out items that are not currently of interest" ([eagereyes](https://eagereyes.org/blog/2012/visweek-2012-digest-part-1)). Munzner puts hue in the **identity** channel group, separate from magnitude channels ([marks/channels](https://www.cs.ubc.ca/~tmm/courses/547-17/slides/marks-4x4.pdf), [colour](https://www.cs.ubc.ca/~tmm/courses/547-17/slides/color-4x4.pdf)); **[UNVERIFIED]** her explicit treatment of *highlighting as a reserved channel* was not located in an open source. Material 3 assigns tertiary to "contrasting accents that can be used to balance primary and secondary colors", used "sparingly for additional accents, highlights, or subtle gradients" ([M3](https://m3.material.io/styles/color/advanced/apply-colors)); NN/g's 60-30-10 reserves the accent "for what you want to stand out the most" and says "**Limit your palette to three colors**" ([NN/g](https://www.nngroup.com/articles/color-enhance-design/)). Atlassian ships `color.chart.brand` — "Our primary color for data visualization. **Use when only one color is required.**" ([Atlassian](https://atlassian.design/foundations/color/data-visualization-color)). **[UNVERIFIED]** Power BI's theme roles (`good`/`neutral`/`bad`/`maximum`/`center`/`minimum`/`tableAccent`) and Tableau's dim-rather-than-recolour highlight were not confirmed from primary sources this run.

**Harm evidence — yes, conditionally.** Haroz & Whitney varied colour "variety" 1–7: for a **known target** the cost is "a few milliseconds per additional category", but for an **oddball (unknown) target** accuracy was "significantly affected by the amount of variety", random layouts showing "a marked decline" (~8000 ms at variety 7 vs ~1000 ms at variety 1); category-counting showed "a marked, sigmoidal fall-off… severely impaired — F(1,4) = 96, p<0.005" ([source](https://escholarship.org/content/qt4cs762vs/qt4cs762vs.pdf)). Reading an unfamiliar diagram is the *unknown-target* case. The similarity qualifier matters: search "decreases as distractor-distractor similarity within a display decreases", "mainly when the target-distractor similarity is also high", and "the **minimum** target-to-distractor feature difference was a stronger predictor of behavior than the mean" ([Mihali & Ma](https://www.biorxiv.org/content/10.1101/2020.08.10.244707v1.full)) — a second accent costs in proportion to how *close* it sits to the first. For diagrams, Moody's **Graphic Economy**: "the human ability to discriminate between perceptually distinct alternatives (span of absolute judgement) is around **6 categories**: this defines an effective upper limit for graphic complexity"; colour "if not used carefully… can undermine communication" and "should not be used as the sole basis for distinguishing between symbols" ([PoN, RE'09](https://homepages.uc.edu/~niunn/courses/RE-refs/PoN-RE09.pdf)). Tufte's 1+1=3: elements "interact, creating non-information patterns", noise "directly proportional to the contrast in value… between figure and ground", and the one-accent-on-neutral pattern — "**Color spots against a light gray or muted field highlight and italicize data**" ([NAS-94-002](https://www.nas.nasa.gov/assets/nas/pdf/techreports/1994/nas-94-002.pdf)). His own colour-count number is "more than **20 or 30** colors… negative returns", so the repeated "5–8" rule is **not** Tufte's; the defensible number is Moody's ~6. "Smallest effective difference" is *Visual Explanations* (1997) p.73 ([trail](https://blas.com/visual-explanations/)). **Confirmed absences:** no study directly tests *adding a second highlight colour to an already-coloured chart*; NN/g states no "only one accent" rule; Healey's canonical preattentive page carries no colour-count limit ([Healey](https://www.csc2.ncsu.edu/faculty/healey/PP/)).

## 4. Diverging scales and their two poles

Poles are **perceptually constrained, not brand-chosen**. ColorBrewer: extremes get "dark colors that have **contrasting hues**", schemes are "designed to be **symmetrical**", and the tool offers only "**Pick** a color scheme" — no free colour entry exists ([schemes](https://colorbrewer2.org/learnmore/schemes_full.html), [tool](https://colorbrewer2.org/)). Kovesi is the hardest constraint: end points "should have the **same chroma**, and if the lightness values reverse… the **same level of lightness**"; even canonical red/blue fails naively — "RGB red and blue have lightness levels of 53 and 32 and chroma values of 105 and 134" — and aesthetics explicitly yield: blue-grey-yellow "might not be one's first choice **aesthetically**… but it allows the maximum range of lightness values" ([arXiv 1509.03700](https://arxiv.org/pdf/1509.03700), [colorcet](https://colorcet.com/)). Moreland chose poles for cross-cultural semantics and CVD: "we carefully chose two colors that most naturally have 'low' and 'high' connotations"; "the cyan to mauve color map is much easier to see by individuals with deuteranope or protanopic vision" ([ColorMapsExpanded.pdf](https://www.kennethmoreland.com/color-maps/ColorMapsExpanded.pdf)). matplotlib states it purely in lightness — "approximately equal minimum L\* values at opposite ends… BrBG and RdBu are good options" ([colormaps](https://matplotlib.org/stable/users/explain/colors/colormaps.html)); d3's nine diverging schemes are all ColorBrewer names ([d3](https://d3js.org/d3-scale-chromatic/diverging)). Datawrapper treats brand colour as a thing to work *around*: "the logo color might evoke unwanted associations. Or it might be too bright for small areas, or too saturated for big areas", and of a built gradient — "**They don't even need to include your original color codes**"; Finn.no "skipped the blue in >1 color charts… users could interpret categories colored in that blue as 'more brand-related'" ([style guides](https://www.datawrapper.de/blog/colors-for-data-vis-style-guides), [which scale](https://www.datawrapper.de/blog/which-color-scale-to-use-in-data-vis)). Design systems agree: Carbon ships red–cyan ("natural association with temperature") and purple–teal ("good for data with no temperature associations"), with IBM Blue 60 in sequential and categorical but **never as a diverging pole** ([Carbon](https://carbondesignsystem.com/data-visualization/color-palettes/)); Adobe Spectrum ships Orange-yellow-seafoam / Red-yellow-blue / Red-blue diverging and Viridis/Magma/Rose/Cerulean/Forest sequential, and the **word "brand" does not appear on that page** ([Spectrum](https://spectrum.adobe.com/page/color-for-data-visualization/)); Atlassian states "Sequential and divergent chart colors are **not currently supported**"; Polaris Viz is deprecated ([README](https://raw.githubusercontent.com/Shopify/polaris-viz/main/README.md)). **Key absence:** *no source explicitly forbids* brand colours as poles — the prohibition is **constraint-implied, not cited**. The genuine two-hue consumer is the **bivariate choropleth** (sequential × sequential), but a 4×4 map is 16 colours and that guide gives **no hue-pairing guidance at all** ([Axis Maps](https://www.axismaps.com/guide/bivariate-choropleth)), while the published tooling picks the pair by **rotating hue angles in HCL** ([Bivariate Hue Blending](https://link.springer.com/chapter/10.1007/978-3-031-61698-3_9)) — the same mechanism as a golden-angle walk, not a brand token.

## 6. Answers

**1. Jobs left over for a second brand hue**, ranked by attestation:
1. **A reserved emphasis/highlight/selection colour** — best attested (Highcharts, Cytoscape, deck.gl, mxGraph, Plotly). But note *what these are*: a fixed hue chosen to sit **outside** the content palette (`#00FF00`, `rgb(255,0,255)`, navy `[0,0,128]`), mostly for **interactive chrome**. A static diagram has no selection state, and "the highlighted series" is already solved by grey-out using the **primary** accent. This argues for a *reserved, walk-excluded highlight token*, not for a second **brand** hue.
2. **The second pole of a diverging scale** — a genuine two-hue need, but §4 shows poles are perceptually constrained; brand can legitimately supply at most **one** pole, the other chosen for chroma/lightness symmetry and CVD separation. Not a free brand slot.
3. **Bivariate / two-layer map encodings** — real need for two hue anchors, weakly attested, and the published method derives the pair by HCL hue-angle rotation, which the categorical walk already provides.
4. **Structural alt-surfaces** (cluster/subgraph backgrounds, alternating sections) — **no job left**. Mermaid *derives* `secondaryColor`/`tertiaryColor` from `primaryColor` and reuses them as `cScale1`/`cScale2`.
5. **A single-mark colour for one-series charts** — real (`markColor`, `color.chart.brand`), but that is the **primary** accent, not a second one.

**2. Is emphasis/highlight/selection a real distinct colour role?** **Yes**, in systems owning a whole interactive surface: Highcharts `highlightColor` / `--highcharts-highlight-color-*`; Cytoscape.js `:selected` (`#0169D9`); deck.gl `highlightColor` + `autoHighlight`; mxGraph/draw.io `HIGHLIGHT_COLOR`, `VERTEX_SELECTION_COLOR`, `EDGE_SELECTION_COLOR`; Plotly `layout.activeshape.fillcolor` plus deliberately-empty `selected.marker.color` slots. **No**, in libraries scoped to the plot rectangle: ECharts has the *states* (`emphasis`/`blur`/`select`) but expresses them via `liftColor()` and opacity; Carbon as a −7% lightness delta; Highcharts' own hover as `brightness`/`opacity`. Vega, Observable Plot and Excalidraw have no such role at all.

**3. Do diverging scales draw poles from brand colours?** **No — independent perceptual palettes, near unanimously.** Every design system shipping a diverging palette ships a brand-free one (Carbon, Spectrum); Atlassian ships none; Datawrapper says the output "doesn't even need to include your original color codes". The constraints (equal chroma, mirrored lightness, cool→warm ordering, neutral midpoint, minimum hue-angle separation) are why — and this is **constraint-based, not prohibition-based**: "we used our brand colours" is refuted by measurement, not by citation.

**4. Does a second accent harm diagram legibility?** **Yes, conditionally — and the conditions match diagrams.** Cost is near-zero for *known-target* search but steep for *unknown-target* scan-and-notice tasks (Haroz & Whitney: ~8000 ms vs ~1000 ms at variety 7 vs 1; category-counting F(1,4)=96, p<0.005) — exactly what a reader does with an unfamiliar diagram. Harm scales with the **minimum** distance between the two accents in colour space (Mihali & Ma) and with unsystematic application. Moody caps diagram symbol categories at ~6. **No study directly tests "second accent on an already-coloured chart"** — the inference is from colour-variety and visual-search work, and this repo's `style-guide.md` already asserts the conclusion without external citation.
